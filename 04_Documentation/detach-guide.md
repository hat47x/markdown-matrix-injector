# 原本とMMIを外す手順

原本を廃止すると決めた文書について、標準のMarkdownとして成り立つ状態へ移し、原本とMMIを外しても困らないことを確かめる手順です。切り離しは選択肢であり、必須ではありません。Excelで書き続ける文書は、つないだまま使い続けてかまいません。文書、章、シートなどの単位で、切り離す範囲を人が決めます。

この手順は、基本設計書キット（`04_Documentation/kits/basic-design`）の複製で確かめています。確かめた範囲と未確認の範囲は、末尾にまとめました。

## 事前に決めること

- 切り離す文書。ほかの文書を、つないだまま残してかまいません。
- 原本の保管先。原本を捨てるのではなく、ワークスペースの外へ保管することを勧めます。
- 切り離した文書の置き場所。元の文書とは別のフォルダーにします。

## 手順

以下は、リポジトリの外から実行する場合の例です。`--root`には、文書と原本が入るフォルダーを指定します。

1. 現在の状態を確かめます。参照の誤りが残ったまま切り離さないでください。

   ```sh
   mmi check 基本設計書.md --root .
   ```

2. 切り離した文書を作ります。小さい表は本文へ展開され、別紙になる大きい表と、本文が参照するローカル画像は、出力先の隣に置かれます。図形の範囲画像（region-snapshot）もローカル画像として扱われます。

   ```sh
   mmi materialize 基本設計書.md -o detached/基本設計書.md --root .
   ```

   取り込み済みの表・画像・図形の範囲画像・Treeが、現在の原本と変わっていた場合、終了コードは1になります。原因を確かめ、取り込み直すか、変更を受け入れてから進めてください。

3. 原本を指す文章を直します。`materialize`は、本文中の通常のリンクを書き換えません。次の手順で検査すると、原本へのリンクが残っていれば`MMI_DETACH_BROKEN_LINK`として報告されます。切り離した文書の側で、原本へのリンクを外すか、保管先を示す文に直してください。表を参照していると書いた文も、切り離した後は事実と異なるため、あわせて直します。

4. 原本を外した状態で検査します。原本のあるフォルダーを、検査の間だけ別の場所へ移してください。

   ```sh
   mmi detach-check detached/基本設計書.md --root .
   ```

   終了コードが0なら、MMIの参照、未実体化の記号、旧「別紙」カード、壊れたローカルリンク、ワークスペース外へのリンクが残っていません。1なら、報告された箇所を直して、再度検査します。

5. 原本を保管先へ移します。手順2〜4の結果を確かめてから行ってください。台帳（`mmi-ledger.json`）は、取り込みの履歴として原本と一緒に保管すると、後から出典を辿れます。

6. MMIを外した環境で、切り離した文書を開いて確かめます。表と画像が標準のMarkdownとして読めることを確認します。次の「MMIを外す」を参照してください。

## MMIを外す

文書を切り離した後、MMIの拡張とCLIを外せます。切り離した文書・画像・台帳は残るため、外した後も標準のMarkdownとして読めます。

1. **VS Code拡張を外す。** 拡張ビューで「Markdown Matrix Injector」を選び、アンインストールします。コマンドでは次のとおりです。

   ```sh
   code --uninstall-extension hat47x.markdown-matrix-injector
   ```

2. **CLIを外す。** 配布tarballをグローバルに入れた場合は、パッケージ名でアンインストールします。

   ```sh
   npm uninstall --global markdown-matrix-injector
   ```

   `npx`で一時実行しただけなら、作業用のキャッシュを消す必要はありません。プロジェクトに開発用の`node_modules`を置いた場合は、そのプロジェクトの依存から外します。

3. **設定を消す。** `markdownMatrixInjector.*`の設定は、拡張を外すと使われません。残っても文書には影響しませんが、不要なら設定JSONから削除します。

4. **残すものを確認する。** 切り離したMarkdown、画像、別紙、`mmi-ledger.json`は残します。台帳は、原本を保管した場所と一緒に置くと、後から出典を辿れます。`mmi-review-basis.json`や`mmi-ledger.json`は、MMIを外した後も通常のJSONとして読めます。

5. **表示を確かめる。** VS Code標準のMarkdownプレビュー、または任意のMarkdown閲覧ツールで、表・画像・リンクが読めることを確認します。MMIのプレビュー拡張が無い状態で、`![[...]]`が残っていないことも確認します（`detach-check`が0件なら残っていません）。

MMIを外すことは、文書の価値を下げる作業ではありません。Excelで書き続ける範囲はつないだまま、切り離した範囲だけを標準Markdownとして持ち続けられます（ADR-0019 D3）。

## 一部だけを切り離す場合

文書全体ではなく、一部の章や表だけを切り離す場合も、同じ手順を使えます。切り離さない部分は、元の文書にMMI参照のまま残してください。切り離した文書と元の文書を、同じ名前で置かないようにします。Detachedへ移した割合を、成功の指標にしないでください。
