## MMIとは何か
Markdown Matrix Injectorは、Excel・CSV・XMLを正本として残し、テキスト文書から必要な部分だけを読み取り専用で参照するための公開規約（MMI Notation）と、その参照実装（VS Code拡張）です（決定正本: ADR-0012）。

本プロジェクトが重視するのは次の4点です。
1. **正本を変更しないこと（恒久的な規則）**: 参照機能から元データを変更してはなりません（Read-only MUST）。AIエージェントに編集を任せる場合も、この制約を守ります。
2. **複製せずに参照すること**: 表を貼り付けて二重管理する代わりに、参照する対象を記述します。これにより、正本と文書の食い違いを構造的に防ぎます。
3. **Markdownで表を扱いやすくすること**: 表やマトリクスの多い設計文書でも、Markdown中心の執筆を続けられるようにします。
4. **納品時の体裁を整えること**: 大きな表を別の表示形式に切り替える機能（Smart Fallback）や印刷制御により、巨大表やPDF出力時の表示崩れに対処します。実際のPDFで動作を確認済みです。

## 読者ごとの価値
ここでは、導入判断者、概念実証の担当者、運用担当者、AIエージェントの開発者に分け、各自が何を判断できるかをまとめます。

### 導入判断者の価値
- 元データを変更しない仕組みと、大きな表の表示切り替え（Smart Fallback）、改ページ（`pageBreak`）、用紙の向き（`orientation`）を合わせて評価し、導入時のリスクを見積もれます。
- 概要、チュートリアル、利用場面、記法の参照文書の順に確認することで、組織内で導入を説明するための根拠を揃えられます。
- **判断できること**: Wordの代わりに使えるかを、正本の保護と納品時の印刷品質の両面から判断できます。

### 概念実証の担当者にとっての価値
- `![[...]]`記法と`columns`、`grep`、`header`などの基本的なパラメータを使い、30分以内に最初の埋め込みを再現できます。
- 失敗した場合も関連文書をすぐに参照できるため、検証記録を残しながら採用できるか判断しやすくなります。
- **判断できること**: 短時間で結果を再現できるか、問題が起きた場合に調査を始められるかを確かめ、自分たちのチームで使えるか判断できます。

### 運用担当の価値
- 文書に表を貼り直す代わりに正本を参照するため、改訂時の差分管理や正本との照合にかかる手間を減らせます。
- 大きな表をカード形式で表示することで、日常の編集のしやすさと納品時の印刷体裁を両立できます。
- **判断できること**: 日常の更新にかかる手間と納品時の品質を両立できるかを確かめ、運用を続けられるか判断できます。

### AIエージェントの開発・導入担当者にとっての価値
- AIエージェントが設計書を書く場合も、表のコピーではなく参照を挿入させるための規約として使えます。`MMI_FILE_NOT_FOUND`などの診断コードで参照先を機械的に確認できるため、生成した文書の参照が有効かどうかを自動検査に組み込めます。
- `query-evidence`の出力は、AIエージェントが作成した文書と正本が一致するかを調べる際の照合基準になります。
- 必要な部分を宣言的に参照するため、大きな正本ファイルの全内容をAIの入力に展開する必要がありません。
- **判断できること**: AIエージェントによる文書生成を導入しても、読み取り専用の参照と機械的な検査によって正本と文書の整合を守れるか判断できます。

## 主な機能
- `![[...]]` 記法でCSV / XLSX / XML Spreadsheet 2003を埋め込む
- `columns`, `transpose`, `grep`, `header` などで必要な範囲だけ切り出す
- `caption`, `id`, `pageBreak`, `orientation` で印刷や相互参照を補助する
- 大きな表やファイル全体を参照する場合は、Smart Fallbackによってカード表示へ切り替える
- 入力補完（Autocomplete）、診断（Diagnostics）、貼り付けやドラッグ・アンド・ドロップで記法の入力を支援する

## 現時点の制約
- **プレビュー描画（G1）**: HTMLの構造・クラス・属性は単体テスト167件で確認済みです。VS Codeでの実際の見た目は、画面を操作する手動試験で確認してください（`04_Documentation/vscode-e2e-testing.md`の確認項目F）。
- **PDF/印刷（G2）**: `pageBreak` / `orientation` のPDFへの反映は生成器に依存します。今回確認した経路はMMIで展開済みのHTMLからWeasyPrint 69.0への変換です。手順は [利用マニュアル](user-manual.md#pdfを作る) を参照してください。Markdown PDF拡張からの直接出力は未検証です。
- **XML**: XML Spreadsheet 2003のみ対応。汎用XMLはエラー表示になります。
- 実際の画面の最終確認には、利用する環境やVS Codeのバージョンの違いが影響します。
- 本書では`overview.md`に求められる製品価値の説明を優先しています。詳しい操作手順は`tutorial.md`を参照してください。

## よくある質問
### Q1. この文書だけで導入可否を決められますか？
A1. いいえ。本書では製品価値と次に読む資料を説明します。導入するかどうかは、チュートリアルの再現性と利用場面への適合性を確かめてから判断してください。

### Q2. Word 代替の観点で最初に見るべき項目は何ですか？
A2. 正本を変更しない仕組み、大きな表への対応（Smart Fallback）、改ページや用紙の向きの制御（`pageBreak`、`orientation`）を優先して確認してください。

### Q3. どの読者がどの文書を先に読むべきですか？
A3. 原則として、概要、チュートリアル、利用場面、記法の参照文書の順に読んでください。時間が限られる場合も、本書で全体像を確かめてからチュートリアルへ進むことを勧めます。
