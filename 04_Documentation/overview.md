# MMIの概要

Excelなどで作った表を設計書に貼り付けると、元の表を直すたびに貼り直す必要があります。MMIは、**元のファイルをそのまま使いながら、文書には必要な部分だけを表示する**ための仕組みです。

このページでは、MMIが役立つ場面、今できること、導入前に確かめたいことを説明します。操作を試したい方は[チュートリアル](tutorial.md)へ、具体的な作業は[利用マニュアル](user-manual.md)へ進んでください。

## MMIで変わること

たとえば、Excelで管理している要件一覧から「要確認」の行だけを設計書に載せたいとします。従来のように表をコピーする代わりに、MMIでは**どのファイルのどの範囲を見せるか**を文書に書きます。プレビューには、指定した範囲が表として表示されます。

元の表はExcelで編集し続けられます。MMIの参照機能は、そのファイルを読み取るだけで、書き換えません。一方、表を説明する本文の文章まで自動で更新されるわけではありません。原本を変更した後は、説明が現在の表に合っているかも確認してください。

MMIが扱う文書はMarkdownという、見出しや表を簡単な記号で書くテキスト形式です。現在の参照実装は、文書を編集するソフトウェア「Visual Studio Code（VS Code）」の拡張機能として提供しています。記法は特定の画面だけに依存しない公開規約（MMI Notation）として管理しています。

## 大切にしている四つの点

1. **元のファイルを守る。** MMIからExcelなどの原本を書き換えません。読み取りができない場合も、成功したふりをせず問題を示します。
2. **同じ表を二重に管理しない。** 表の値をコピーせず、原本の場所と表示範囲を指定します。原本の改訂に合わせて、参照先の値を読み直せます。
3. **文書を読みやすくする。** 大きな表は別紙へのリンクを示すカードに切り替えたり、表示する行や列を絞ったりできます。
4. **納品時の見え方も確かめる。** 改ページや用紙の向きなどを指定できます。ただし、PDFへの反映は変換に使うソフトに依存します。確認済みの経路は、MMIで展開したHTMLをWeasyPrint 69.0でPDFにする方法です。

この基本方針の根拠は[ADR-0012](../01_Plans/adr/ADR-0012-mission-redefinition-notation-as-governance-boundary.md)です。人が慣れた道具で書き続けることを尊重する、現在の製品全体の方針は[ADR-0019](../01_Plans/adr/ADR-0019-ai-era-sier-document-value-and-policy.md)にあります。

## どんな人に役立つか

| 立場 | 確かめたいこと |
| --- | --- |
| 導入を判断する人 | 原本を守りながら、文書の更新や納品準備を続けられるか |
| 初めて試す人 | 手元の表を読み取って、プレビューに表示できるか |
| 文書を保守・納品する人 | 原本の変更を文書に反映し、別紙やPDFを確認できるか |
| AIを使って文書を作る人 | AIが参照先を指定した後、その参照が正しいか機械的に検査できるか |

AIに文書を書かせる場合も、参照先の確認は必要です。`MMI_FILE_NOT_FOUND`などの診断コードや、`query-evidence`で得られる照合情報を使えます。必要な表だけを指定すれば、原本全体をAIへ渡さずに済む場面もあります。ただし、AIが書いた説明文の意味までMMIが保証するわけではありません。

## 今できること

- Excel（.xlsx）、CSV、XML Spreadsheet 2003の表を、`![[...]]`という記法で文書に表示する。
- `columns`、`grep`、`header`、`transpose`で、表示する列や行、見出し、行列の向きを調整する。
- `caption`や`id`で表題と文書内の参照先を付ける。`pageBreak`と`orientation`で印刷用の指定を加える。
- 大きな表やファイル全体を、別紙カードとして案内する。
- 入力候補、参照先の診断、貼り付け支援などを使って記法を作る。候補は利用者が確かめてから採用する。

これらは表を表示する機能の説明です。取り込みや切り離しなど、MMIのほかの機能とその検証状況は[現在の作業](../01_Plans/README.md)で確認できます。計画に載っている機能が、すべて実装済みという意味ではありません。

## 導入前に知っておきたい制約

- 一般的なXMLを表として読む機能ではありません。表の参照として対応するのはXML Spreadsheet 2003です。
- Excelの配色、結合セル、数式の再計算をそのまま再現するものではありません。
- プレビュー表示のHTML構造・クラス・属性は単体テスト167件で確認した記録があります（G1）。実際の画面表示は利用環境でも確かめてください。[VS Codeでの確認手順](vscode-e2e-testing.md)の確認項目Fを参照できます。
- PDFでの`pageBreak`と`orientation`の扱いは、変換に使うソフトによって変わります（G2）。[PDFの作り方](user-manual.md#pdfを作る)を参照してください。VS CodeのMarkdown PDF拡張からの直接出力は、ここでいう確認済み経路ではありません。
- 原本と文書を一緒に管理する際は、ファイルの置き場所にも注意が必要です。
