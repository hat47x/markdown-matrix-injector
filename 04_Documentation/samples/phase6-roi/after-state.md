# 利用後サンプル（MMI運用）

## 想定コンテキスト
- 設計書本文: Markdown
- 参照データ: Excel/CSV/XML を正本としてリンク注入
- レビュー共有: Markdown/PDF（同一ソース）

## 観測観点と手順

### 観点1: レビュー準備工数（時間短縮）
- 手順:
  1. Markdown本文を更新。
  2. `![[...]]` 記法で正本データを参照し、手動貼り付けを省略。
  3. プレビューで図表表示とリンクを確認してレビュー依頼。
- 観測値:
  - 準備開始〜レビュー依頼送信までの分数。

### 観点2: 参照不整合の発生率（品質）
- 手順:
  1. Diagnostics でリンク切れ/シート不在を事前検出。
  2. レビュー指摘票で参照不整合件数を集計。
- 観測値:
  - 不整合件数（件/ドキュメント）。

### 観点3: 監査時の追跡時間（監査容易性）
- 手順:
  1. 質問対象の注入記法から正本ファイルと範囲を特定。
  2. 同一Markdown上で根拠位置を提示。
- 観測値:
  - 回答に必要な時間（分）。

## 期待結果（利用後）
- 利用前比でレビュー準備時間の短縮を確認できる。
- 参照不整合が事前検知により減少する傾向を確認できる。
- 監査質問への回答時間が短くなることを示せる。

## 制約
- 初期導入時は記法学習コストにより、短期的に工数が増加する場合がある。
- 巨大表や特殊印刷要件は Smart Fallback/印刷設定への習熟が必要。
