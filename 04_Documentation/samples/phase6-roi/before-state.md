# 利用前サンプル（従来運用）

## 想定コンテキスト
- 設計書本文: Word
- 参照データ: Excel/CSV（別ファイル、手動参照）
- レビュー共有: PDF化 + メール/チャット

<a id="before-observation-method"></a>
## 観測方法（利用前）

### 観点1: レビュー準備工数（時間短縮）
- 手順:
  1. Word本文を最新化。
  2. 参照表をExcelからコピー＆整形貼り付け。
  3. 図表番号と参照文を手動修正。
- 観測値:
  - 準備開始〜レビュー依頼送信までの分数。

### 観点2: 参照不整合の発生率（品質）
- 手順:
  1. レビュー指摘票から「参照先の誤り」「古い表の貼付」を抽出。
  2. 1ドキュメントあたりの件数をカウント。
- 観測値:
  - 不整合件数（件/ドキュメント）。

### 観点3: 監査時の追跡時間（監査容易性）
- 手順:
  1. 監査質問（例: 「この表の正本は何か」）を受領。
  2. 正本ファイル、更新者、根拠箇所を収集。
- 観測値:
  - 回答に必要な時間（分）。

<a id="before-expected-observation-results"></a>
## 期待観測結果（利用前）
- 手作業が多く、修正たびに工数が増える傾向を確認できる。
- 参照不整合がレビュー後半で発見されやすいことを可視化できる。

<a id="before-constraints"></a>
## 制約（利用前）
- チームごとの文書テンプレート差異により工数の絶対値は変動する。
- 既存運用で自動連携マクロ等を使っている場合、差分が小さく見える可能性がある。
