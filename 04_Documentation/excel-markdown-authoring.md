# Excelの設計書や新しい表を参照してMarkdownを書く

既存のExcel設計書は、これまで使ってきた書式のまま更新できます。Markdownには、必要な表への参照と、その説明を書きます。新しい表もExcelで作成・保存してから、同じ方法で参照します。設計書全体をMarkdownに変換する必要も、Excelの利用をやめる必要もありません。

## 最初の参照を作る

ExcelブックとMarkdown文書を、参照が許可された作業領域内に保存します。次の例では、ファイルを以下のように配置します。ファイル名と範囲は説明用のものです。

```text
docs/
  設計.md
  masters/
    設計.xlsx
```

VS Codeで`設計.md`を開き、本文の挿入位置でコマンドパレットから`MMI: 参照を作成・編集（ブック→シート→範囲→確認）`を実行します。ブック、シート、範囲、表示方法を選び、参照先と表示内容を確かめてから挿入します。日本語表示のコマンド名です。途中で取り消した場合は本文を変更しません。

「画面項目」シートの`A1:D8`を、先頭行を見出しとして表示する例です。

```markdown
## 画面項目

![[./masters/設計.xlsx#画面項目|A1:D8?header=first]]

差し戻すときはコメントを必須とします。
```

表の値を本文へ手入力で写すのではなく、表を参照します。適用条件や説明は、通常のMarkdownで書きます。見出しや列を選ぶ指定の正確な意味は[記法仕様](spec/mmi-notation-v1.md)を参照してください。

## 新しい表もExcelで作る

人がExcelで表を作り、保存します。既存のブックに表やシートを追加しても、新しいブックを作っても構いません。Excelの「テーブル」機能やMMI専用テンプレートは必須ではありません。

VS Codeの表の目録から探すか、上の参照作成コマンドでブックとシートを選びます。目録を更新するコマンドは`MMI: 表の目録を更新`です。表の候補が見つからなくても、シートそのものは目録に残ります。シートのコンテキストメニューから`MMI: このシートから範囲を指定して参照を作成`を選ぶと、そのシートを保ったまま範囲選択へ進めます。目的の表が候補に現れない場合は、`A1範囲を入力…`を選びます。原本で確認した`A1:D20`のような範囲を直接指定できます。検出候補へ無理に合わせる必要はありません。範囲を入力した後も、実際の表示結果をプレビューで確認してから挿入します。クリップボードからの候補取得が使えない場合も、この手順で作業できます。

## Excelで保存した後に確認する

MMIが読み込むのは保存済みのファイルです。Excelで値を変えたら保存し、VS CodeのMarkdownプレビューで確認します。開いているMarkdownがそのブックを参照している場合、MMIはブックの一時保存情報（Workbook cache）を無効にし、Markdownのプレビューと参照先の診断を再確認しようとします。

表示を確実に見直したい場合や、自動更新されない場合は、コマンドパレットから`MMI: 参照中の表を再確認`を実行します。この操作は表の目録を更新するだけではありません。MMIが保持するブックの一時保存情報を消し、開いているMarkdownの診断とプレビューを再確認します。`MMI: 表の目録を更新`とは別の操作です。

保存直後にファイルを読めなくなった場合は、以前の表示や診断を「現在の保存内容を確認済み」とは扱わないでください。原本を再び読めるようになってから確認し直してください。シート名を変えた場合は、参照先が見つからない診断を手掛かりに参照を直します。固定範囲について、意味に基づく追従や自動的な範囲拡張は行いません。

この自動更新と明示再確認の実VS Code＋Excelでの確認状況は[併用執筆の計画](../01_Plans/issues/issue-0211-vscode-excel-coauthoring-flow.md)で管理しています。数式の値もExcelで保存された内容に依存します。MMIがExcelと同じ再計算をする前提で使わないでください。

## エラーや警告の言語を選ぶ

「問題」パネル、Markdownプレビュー、ホバーに出るMMIのメッセージ（シートが見つからない、見出しが変わった、など）は、VS Codeの表示言語に合わせて出ます。日本語の言語パックを入れていない英語表示のVS Codeでも日本語で読みたい場合は、設定`markdownMatrixInjector.language`を`ja`にしてください。既定の`auto`はVS Codeの表示言語に従い、MMIに文面のない言語では英語で表示します。

シート名を変えて参照が切れたときは、メッセージが近い名前のシート（たとえば`画面`が`画面項目`に変わった場合）か、そのブックにあるシートを示します。コマンドラインの出力とエラーコードは、これまでどおり英語です。

## 行や列を増やしたら参照範囲も確かめる

`A1:D8`の参照で、Excelの9行目へ項目を足しても、その行は範囲に含まれません。既存の参照上で参照作成・編集コマンドを使うか、範囲を`A1:D9`へ直し、見出し・列・末尾の項目をプレビューで確かめます。

指定した範囲の中で行や列を挿入・削除した場合も、表示する内容が変わることがあります。参照のエラーが出なくても、目的の表が表示されているか確認してください。シート名やファイルの位置を変えたときは、その指定も見直します。候補が複数ある場合は参照先を選び、自動的に同じ意味の表へ結び直されるとは考えないでください。

原本ファイルを移動・削除したり、大きく構成を変えたりする前には、VS Codeのエクスプローラーで原本を右クリックし、`MMI: この原本を参照中のMarkdownを確認`を実行できます。Linked参照、採用済みExtracted資産の出典、通常のローカルリンクをまとめて表示し、選んだMarkdownの該当行を開きます。この操作は参照を書き換えません。影響先を確認したうえで、人が変更する範囲を決めます。

## 原本を確認して執筆へ戻る

参照先のファイル・シート・範囲は、参照記法から確認できます。別紙カードの「外部アプリで開く」から原本ファイルを開ける場合は、それを使えます。原本の特定のセルまで自動的に移動することは保証していません。

参照の修正を確定する前に、表示する表と本文の説明が合っているかを確かめます。確定後に戻す場合はVS CodeのUndoを使います。ファイル不在、読込み失敗、複数の似た候補が出た場合は原本の保存先と指定を確認し、古い表示や先頭の候補だけを根拠に確定しないでください。

図形や配置を残す必要のある範囲では、表だけでは元の内容を表しきれない場合があります。[利用マニュアル](user-manual.md)と[現在の作業](../01_Plans/README.md)で、画像等の対応経路と検証範囲を確認してください。
