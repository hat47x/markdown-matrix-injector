# Excelの設計書や新しい表を使ってMarkdownを書く

既存のExcel設計書は、使い慣れた書式のまま更新できます。Markdownには必要な表の参照と説明を書きます。新しい表もExcelで作成・保存してから、同じ方法で参照します。Markdownへ全体を変換したり、Excelの利用を終えたりする必要はありません。

## 最初の参照を作る

ExcelブックとMarkdown文書を、参照を許可されたワークスペース内へ保存します。次の例では、ファイルをこのように配置します。名前と範囲は説明用です。

```text
docs/
  設計.md
  masters/
    設計.xlsx
```

VS Codeで`設計.md`を開き、本文の挿入位置でコマンドパレットから`MMI: 参照を作成・編集（ブック→シート→範囲→確認）`を実行します。ブック、シート、範囲、表示方法を選び、参照先と表示内容を確かめてから挿入します。日本語表示のコマンド名です。途中で取り消した場合は本文を変更しません。

「画面項目」シートの`A1:D8`を、先頭行を見出しとして表示する例です。

```markdown
## 画面項目

![[./masters/設計.xlsx#画面項目|A1:D8?header=first]]

差し戻すときはコメントを必須とします。
```

表の値を本文へ手で転記する代わりに参照し、適用条件や説明は通常のMarkdownで書きます。見出しや列を選ぶ指定の正確な意味は[記法仕様](spec/mmi-notation-v1.md)を参照してください。

## 新しい表もExcelで作る

人がExcelで表を作り、保存します。既存ブックへの表・シートの追加、新しいブックの作成のどちらでも構いません。Excelの「テーブル」機能やMMI専用テンプレートは必須ではありません。

VS Codeの表の目録から探すか、上の参照作成コマンドでブックとシートを選びます。目録を更新するコマンドは`MMI: 表の目録を更新`です。表候補が0件でもシート自体は目録に残ります。シートのコンテキストメニューから`MMI: このシートから範囲を指定して参照を作成`を選ぶと、そのシートを保ったまま範囲選択へ進めます。範囲の候補に目的の表が出ない場合は、`A1範囲を入力…`を選び、原本で確認した`A1:D20`のような範囲を明示できます。検出候補へ無理に合わせる必要はありません。入力後も実描画のプレビューを確認してから挿入します。クリップボードからの候補取得が使えない場合も、この手順で作業できます。

## Excelで保存した後に確認する

MMIが読むのは保存済みのファイルです。Excelで値を変えたら保存し、VS CodeのMarkdownプレビューで確認します。開いているMarkdownが保存したブックを参照している場合、MMIはWorkbook cacheを失効し、Markdownプレビューと参照診断の再確認を試みます。

表示を確実に見直したい場合や、自動更新されない場合は、コマンドパレットから`MMI: 参照中の表を再確認`を実行します。この操作は表の目録を更新するだけではなく、MMIが保持するWorkbook cacheを消して、開いているMarkdownの診断とプレビューを再確認します。`MMI: 表の目録を更新`とは別の操作です。

保存直後にファイルを読めない場合は、以前の表示や診断を「現在の保存内容を確認済み」とみなさず、原本が再び読める状態になってから再確認してください。シート名を変えた場合は、参照先が見つからない診断を手掛かりに参照を直します。固定範囲の意味上の追従や自動拡張は行いません。

この自動更新と明示再確認の実VS Code＋Excelでの確認状況は[併用執筆の計画](../01_Plans/issues/issue-0211-vscode-excel-coauthoring-flow.md)で管理しています。数式の値もExcelで保存された内容に依存します。MMIがExcelと同じ再計算をする前提で使わないでください。

## 行や列を増やしたら参照範囲も確かめる

`A1:D8`の参照で、Excelの9行目へ項目を足しても、その行は範囲に含まれません。既存の参照上で参照作成・編集コマンドを使うか、範囲を`A1:D9`へ直し、見出し・列・末尾の項目をプレビューで確かめます。

範囲内への行列挿入や削除でも、表示する対象が変わることがあります。参照がエラーにならない場合も、目的の表かを確認してください。シート名やファイルの位置を変えたときは、その指定も見直します。候補が複数ある場合は参照先を選び、自動的に同じ意味の表へ結び直されるとは考えないでください。

原本ファイルを移動・削除したり、大きく構成を変えたりする前には、VS Codeのエクスプローラーで原本を右クリックし、`MMI: この原本を参照中のMarkdownを確認`を実行できます。Linked参照、採用済みExtracted資産の出典、通常のローカルリンクをまとめて表示し、選んだMarkdownの該当行を開きます。この操作は参照を書き換えません。影響先を確認したうえで、人が変更する範囲を決めます。

## 原本を確認して執筆へ戻る

原本のファイル・シート・範囲は参照記法で確認できます。別紙カードの「外部アプリで開く」から原本ファイルを開ける場合は、それを使えます。原本の特定セルへの自動移動を保証するものではありません。

参照の修正を確定する前に、表示する表と本文の説明が合っているかを確かめます。確定後に戻す場合はVS CodeのUndoを使います。ファイル不在、読込み失敗、複数の似た候補が出た場合は原本の保存先と指定を確認し、古い表示や先頭の候補だけを根拠に確定しないでください。

図形やレイアウトを保つ必要がある範囲は、表だけでは表現しきれない場合があります。[利用マニュアル](user-manual.md)と[現在の作業](../01_Plans/README.md)で、画像等の対応経路と検証範囲を確認してください。
