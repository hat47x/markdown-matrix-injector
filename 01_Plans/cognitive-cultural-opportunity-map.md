# 認知機能と文化的体系による発想地図

2026-10-08。状態は発散案。関連作業は[issue-0208](https://github.com/hat47x/markdown-matrix-injector/issues/511)。

MMIの認知支援を、候補の検出・検索から、注意の配分、問いの生成、視点の切替、関係の発見、解釈の比較、構成、継承へ広げる。24の視点から96案を出し、さらに12の交差案を作った。計108案を後の選択材料として残す。件数は探索の広さを示すもので、網羅性や効果の証明ではない。

今回は発想と接続候補を整理する。機能の採用、優先度の変更、モデルの導入は決めていない。各行の動作は将来の機能案であり、現在のMMIが提供する能力ではない。

有望な方向の深掘りは[文脈・条件・問い・判断をつなぐ設計](cognitive-cultural-deepening.md)にまとめた。H01〜H08を四方向へつなぎ、基本設計書キットの条件付き規則を題材に、最初に試す仕事と入出力まで具体化している。

計画へ移した要素と根拠は[採用要素と起票順](cognitive-cultural-adoption-plan.md)で管理する。追加の[適用範囲・文脈・判断経路の分析](cognitive-cultural-boundary-analysis.md)では、条件の重なり、引用の用途、判断前の保留を掘り下げた。108案のIDと発散内容は探索の入口として保つ。

## 1. 広げる中心

利用者が「この表を取り込みたい」と言ったとき、認知支援は次の仕事まで扱える。

| 認知の働き | MMIで広げたい問い | 残せる成果物の例 |
| --- | --- | --- |
| 気づく | 表の外に、意味を変える注記・図形・余白がないか | 注目箇所と原本位置 |
| 分け直す | 表と文章、事実と解釈、値と条件を別に扱えるか | 複数の領域・役割候補 |
| 関係を見る | 部分の意味は、どの文書・業務・時点との関係で決まるか | 関係の仮説と根拠 |
| 視点を移す | 執筆者、利用者、運用担当、引継ぎ担当では何が違うか | 視点ごとの読み方 |
| 問いを作る | 現在の検索語や分類で、まだ問えていないことは何か | 原本へ戻れる問い |
| 比べる | 相違は誤り、条件差、版差、解釈差のどれか | 異同表と未解決点 |
| 構成する | 表・画像・説明をどう並べると仕事を進めやすいか | 出典付きの章・レビュー下書き |
| 先を試す | 条件を一つ変えたら、どの説明や参照を見直すか | 仮定付きの影響候補 |
| 時間を読む | 版、年度、契約、業務周期の違いを保持できるか | 適用時点と再確認条件 |
| 継承する | 次の人が判断を再利用し、必要なら問い直せるか | 根拠・保留理由・再開条件 |

文化的体系を、国や民族の性格分類には使わない。特定の文献、研究、実践が持つ分節・関係・遷移・操作から着想する。文化体系の説明と、MMI向けに追加する設計上の操作を分ける。

既存の[Cultural Substrate Weavingの体系資料][CSW]も参照した。同資料の「採用済み」はCSW内で探索に使えるという意味であり、MMIの採用を意味しない。五行・五大は今回の比較対象として別に扱う。両者の同名要素を一対一に対応させない。

## 2. 現行MMIからの出発点

[製品要求](../00_Prompt/requirements.md)、[ADR-0019](adr/ADR-0019-ai-era-sier-document-value-and-policy.md)、[ADR-0020](adr/ADR-0020-requirement-oriented-cognition-method-selection.md)、[ADR-0021](adr/ADR-0021-candidate-cognition-lifecycle-reproducibility.md)、[Candidate契約](../02_Architecture/candidate-contract-v1.md)を出発点とする。

現在の接続先として、Candidate目録、原本座標、provenance、取り込み台帳、採否・保留レビュー、ローカルhandoff、provider-dependent処理の非同期経路がある。これらの存在は、新しい機能案が実装済みであることや利用価値が確認済みであることを意味しない。

「文化体系を通したら何が変わるか」は、対象へ戻す問いと後続成果物で示す。例えば「華厳的に見る」だけでは案にならない。「同じ表を別の章へ置いた場合に失われる注記を探し、文脈を保持する取り込み案を出す」まで具体化する。

表中の方式は検討の入口であり、実現可能性の評価結果ではない。

| 表記 | この文書での意味 |
| --- | --- |
| M0 | 明示構造、正確な抜粋、利用者が指定した関係を読む |
| M1 | 固定規則、幾何、グラフ、差分、組合せを使う |
| M2 | 類似検索、疎表現、埋め込み等で候補を探す |
| M3 | 閉じた選択肢の判断を比較する |
| M4 | ローカル生成モデルで解釈・質問・構成を提案する |
| M5 | 利用者が外部AIへ渡す材料をローカル生成する |
| 人 | 人が条件・意味・採否を指定する。M0〜M5とは別軸 |

例えばM1で出した問いも、その問いが示唆する関係は推定である。M0で引用できた文の意味が自動的に確定するわけではない。

## 4. 体系を交差した12案

二つを組み合わせる理由は、違う認知操作を同じ対象へ当てられることにある。数学的な直交性を確認した組合せではない。片方だけで同じ成果が得られる場合、交差する必要はない。

| ID | 交差 | 新しく問えること | 機能として残すもの |
| --- | --- | --- | --- |
| X01 | 易×マヤ暦 | 配置が同じでも、業務周期が違えば何が変わるか | 条件変更と適用時点を分けた比較カード |
| X02 | 五行×五大 | 関係循環の改善で、情報の保持・変換・未決部分はどう変わるか | 相互作用図と変換損失表。要素同士の対応表にはしない |
| X03 | 四句分別×ファセット | 一つの種別では扱えない材料を、どの観点に分けると扱えるか | 複合領域の複数表示と新しい分類軸の候補 |
| X04 | ジャイナ×文献校訂 | 本文の相違は、視点や条件を戻しても相違として残るか | 版差・条件差・未解決差を分けた異同表 |
| X05 | ニヤーヤ×ハディース研究 | 引用元へ遡れることと、今回の推論が成り立つことを分けられるか | 出典鎖と推論の橋を別に示す判断材料 |
| X06 | stasis×対位法 | 複数の意見は、同じ争点について反対しているか | 資料・役割ごとの主張と争点の対照表 |

## 5. 同じ材料を通して問いを変える例

以下は架空の設計書を使う説明例である。実データの観測結果や機能の評価結果ではない。

対象は、Excelの顧客登録設計書とする。`B2:H14`に入力項目表、`J4:N12`に画面画像、`B16:H18`に例外注記がある。別の運用文書と、前年度のコピーもある。最初の依頼は「入力項目表をMarkdownへ取り込みたい」。

| 通した視点 | 最初の問いからの変化 | 原本へ戻す確認 | 後続成果物 |
| --- | --- | --- | --- |
| 華厳 | 表を取り込む→表単体で意味が成立するか | 例外注記が必須条件を変えていないか | 表と注記の別Candidate参照、関係の仮説 |
| ジャイナ | 必須か任意か→誰が、いつ、どの操作で必須か | 新規登録と変更登録の条件差 | 条件付きの比較カード |
| stasis | 表と画像が違う→値・用語・設計評価の何が争点か | 画像の表示時点、用語の定義 | 争点別の保留問い |
| ハディース研究 | 3資料が一致する→3資料は独立した根拠か | コピー元と更新経路 | 本文比較とは別の来歴図 |
| マヤ暦 | 前年と同じ→版と年度の両方が同じか | 対象年度、対象リリース、適用期間 | 適用条件と再確認条件 |
| Llull | 見つけた例外を見る→未確認の役割×操作×時点は何か | 実在する組合せだけを利用者と選ぶ | 未検討箇所の確認リスト |
| Bauhaus | 表へ変換する→表、画像、混成のどれが用途に合うか | 値、注記、配置の保持と編集のしやすさ | 比較用の小さな取り込み下書き |

ここで生じた「注記が条件を変える」「コピー元が同じ」などは、確認前には仮説である。文化体系から出た問いの由来と、対象側で得た根拠を別々に残す。資料に戻って何も変わらなければ「有用な追加なし」として閉じてよい。

## 6. 次の選択に使える8つの仮説

108案を先に残したうえで、現行MMIとの接続先が見える案を具体化する。以下の8仮説を小さな試作の入口とし、他の案も選択対象として残す。採用順位と実装範囲は未決である。

| 仮説 | 元の案 | 最小の形と既存の接続先 | 観測したい変化 | 不足するもの |
| --- | --- | --- | --- | --- |
| H01 問いをCandidateに添える | I024/I029/I033/I096 | 原本位置付きの問い・保留理由・再開条件を別の下書きへ出す。Candidate/ledger/reviewを参照する | 後から同じ説明を調べ直す回数が減るか | 問いの保存先、失効条件、reviewへの関連付け |
| H02 条件差を残す比較 | I021/I022/I053、X04 | 人が対応付けた2箇所を引用し、時点・役割・定義欄を持つ比較表を出す | 誤りと条件差を区別して議論できるか | 文中の意味対応はM0では得られない。最初は人が指定する |
| H03 文脈を伴う取り込み | I010/I033/I036 | 選択範囲の近傍注記・画像・図形を追加候補として見せる。共通目録と採否UIへ戻す | 取り込み後に注記不足で原本へ戻る回数が減るか | 距離規則の誤提案、関係の表現、実文書での確認 |
| H04 読解経路と次の手掛かり | I050/I069/I070/I074 | 検索に続く候補と、人が残したしおりをローカル下書きとして出す | 表名が分からない探索を再開しやすいか | 新しい探索UI、記録の明示操作、source更新への追従 |
| H05 複製根拠と来歴の分離 | I034/I041/I042/I044 | digest一致、参照関係、利用者の指定を別の辺として表示する。台帳のidentity区別を使う | 同じコピーを独立根拠として数える誤りに気づけるか | 類似だけでは複製関係を確定できない。由来の確認が必要 |
| H06 未検討の組合せを問う | I004/I077/I080、X10 | 人が選んだ少数の軸で組合せを列挙し、未検討箇所を確認用Markdownへ出す | 従来のレビューに無かった具体的な問いが出るか | 現実に存在しない組合せの除外、質問数の上限 |
| H07 小さな出力比較 | I064/I089/I090/I091 | 既存の表・画像・Tree経路の対応範囲で比較下書きを作る | 利用者が用途に合う出力を選びやすいか | 対応形式ごとの比較、snapshot方式、実機と編集作業の観測 |
| H08 内容と時間を分けた再確認 | I088/I093/I094/I096 | digestによる鮮度と、人が指定した適用期間を別の項目で表示する | 内容不変のまま適用条件が変わる見落としを減らせるか | 時間条件の契約、再開の操作。自動通知は別途設計 |

H01、H02、H06は、人が意味を指定するMarkdownの作業票でも試せる。モデルの導入を先に必要としない。H03、H05、H07、H08は既存の目録や台帳へ近いが、関係・時点・比較の契約を足す必要がある。H04は探索体験としての試作が必要である。

M4/M5を使う場合も、質問や章立ての提案を担う。出典や条件を生成した文章だけで補わず、引用可能なsourceと利用者の判断へ戻す。[認知資産の配布](https://github.com/hat47x/markdown-matrix-injector/issues/507)や[外部AI handoff](https://github.com/hat47x/markdown-matrix-injector/issues/493)は、その必要が具体化してから使う。

### 認知処理としての組み立て

文化的体系は、認知モデルへ指示する文章だけに限定しない。特徴の選び方、候補の探し方、比較軸、質問の型、構成の探索にも使える。108案を処理として組み立てるときは、次の比較ができる。

| 認知処理 | 文化的体系から変えるもの | 単純な方式からの比較 | 主に使う案 |
| --- | --- | --- | --- |

| 関係候補 | 五行・華厳から、同一内容、関連、依存、促進、制約を分ける | 人が指定した辺とグラフ規則→類似による候補辺→閉集合の関係分類。相関を因果へ変更しない | I005/I034/I035 |

M2のscoreを、異なる文化体系の価値や主張の正しさへ変換しない。Fly-inspired、埋め込み、小型分類器、Jev類似のbounded model、ローカル生成モデル等は交換可能な比較対象であり、今回の案のために採用済みとはしない。

### 機能を連携させた利用場面

個々の検出器を増やす以外に、複数の案をつないだ製品像も残す。

| 利用場面 | つなぐ能力 | 利用者に返すもの |
| --- | --- | --- |
| 書き続けながら見直す | 文脈候補、注意の配分、保留条件 | 編集を止めず、利用者がレビューを開いた時点で使える追加材料 |
| 問いから設計書を読む | 目的別索引、近傍の手掛かり、役割・時点、読解経路 | 「どの表か」から始めなくても辿れる資料と次の問い |
| 意見の違いを整理する | 条件付き比較、争点分離、複数資料の並行表示 | 合意点と相違点が残る判断下書き |
| 取り込み方を試す | 材料のまとまり、関係、複数出力の見本 | 表・画像・Tree・参照を混在させた比較用の下書き |
| 引継ぎで理解を再構成する | 来歴、判断の適用条件、未解決問い、役割別入口 | 前任者の結論だけでなく、判断へ至る根拠と再確認箇所 |
| 別案を発想する | 条件反転、未検討組合せ、矛盾の分離、反例探索 | 出典と仮定を伴う複数の構成案。どれも採用前の案として保持 |

これらを一度に実装する必要はない。同じ仕事を助ける案を一つの縦切りへ束ね、通常の参照・抽出に加わる価値を比較する。

## 7. 取り込む段階の進め方

### まず比較するもの

同じ資料と同じ仕事について、現在のMMIだけで作った成果物、文化体系を使わず通常の設計観点で作った案、選んだ文化体系を通して作った案を比較する。複数体系を交差する場合は、各体系単独の結果も必要な範囲で比べる。

体系の名称が増えたことより、問い・注意・資料の配置・構成案がどう変わったかを記録する。体系を通しても同じ案しか出なければ、その場面で追加する理由は弱い。生成モデルを併用した場合は、文化体系の効果とモデルの効果を一つにまとめない。

| 記録すること | 具体的な確認 |
| --- | --- |
| 問いの変化 | 最初には無かった、原本へ戻して答えられる問いが出たか |
| 注意の移動 | 見落としていた注記、条件、版、関係へ実際に注意が向いたか |
| 構成の増分 | 従来案に無かった取り込み方・章立て・読解経路が作れたか |
| 包括化 | 材料を増やしただけでなく、役割・例外・時間差を残してまとめられたか |
| 制御可能性 | 人が視点、対象範囲、質問量、生成の有無、停止を選べたか |
| 後続への残存 | 得られた問いや区別が、後の修正・レビュー・引継ぎに使われたか |
| 負担 | 提案を読む・直す・却下する時間を含め、仕事が進みやすくなったか |

数値閾値や採用条件は、選んだ仕事と資料に合わせて観測前に決める。今回は実測値や全機能共通の合格点を作っていない。既存文書や利用者の経験から判断できる内容と、新しい観測が必要な内容も分ける。

### 機能へ移すときの表現

最初の試作は既存Candidateを参照する別の下書きで始められる。問い、主張、関係のすべてを新しいCandidate kindへ直ちに押し込まない。次の項目は作業票の案であり、公開schemaへの追加は未決である。

| 項目 | 保存したい意味 |
| --- | --- |
| 対象 | Candidateの参照、source locator、根拠のdigest |
| 発端 | 通した体系、使った操作、元の問い |
| 増分 | 生じた問い、対比、構成案、対象側へ戻す確認 |
| 根拠 | 正確な引用・明示関係と、推定した関係の区別 |
| 判断 | 採用、修正、却下、保留、その理由 |
| 再開 | source変更、条件確定、適用期間変更などの再確認条件 |
| 実行 | method、provider/version、入力条件、生成物のdigest |

認識論上の`observed/inferred/abstained`、人の採否、実行の`deterministic/provider-dependent`は既存契約どおり別軸にする。文化体系由来の推定を、人が採用しただけで原本事実へ変更しない。

原本を読み取り専用に保ち、認知機能の有無で同じ参照の描画・診断を変えない。通常の執筆を待たせず、任意のレビュー・下書きとして利用できる形を選ぶ。MMI自身の外部AI自動送信や、モデルの自動取得は追加しない。

## 8. 発散をここで区切る理由と残す余地

候補発見だけでなく、問い、視点、関係、構成、時間、継承まで展開し、表以外の注記・図形・画像・複数版・運用材料にも広げた。定型規則で試せる案と、意味理解や利用者の判断が必要な案の両方を残した。近い案も、利用場面や残す成果物が異なる場合は統合せず残している。

ここからは同じ資料を使い、具体的な違いを読み直す段階へ移れる。ただし、今回の24視点で発想空間が尽きたとは扱わない。

未展開の余地として、口承・語りと索引付き物語、翻訳学の意味対応、演劇の役割交代、料理の組合せと工程、庭園の経路と見え方、保守修繕の実践、アクセシビリティに応じた表現、異なる文書文化の共同作業がある。対応する具体的な資料や仕事が出たとき、既存案にない認知操作を加えられるか検討する。
