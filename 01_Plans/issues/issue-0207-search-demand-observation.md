## Execution Plan

### Proposed solution

設計文書のとおり。検索画面の1回を1セッションとして、最後の依頼の分類（略語・表記ゆれ・言い換え・該当なし・未対応の操作）、結末、選んだ候補の順位と適合度、別名の提案の結果をローカルに記録し、件数だけの集計を利用者が見られるようにする。既定はオフで、依頼文は記録しない。

### Acceptance criteria

- [ ] 既定で何も記録しない。設定をオンにしたときだけ記録し、最初に記録する内容を一度示す。
- [ ] 依頼文・表名・ファイル名・利用者名を記録しない（`includeText`をオンにした場合の依頼文を除く）。型と単体テストで、既定の記録に依頼文が入らないことを固定する。
- [ ] 保存先はワークスペース単位のローカル領域で、リポジトリ内に置かない。1,000件の循環とし、コマンドで集計・書き出し・消去できる。外部への送信経路を持たない（ネットワークを使うコードを含まないことを確認する）。
- [ ] 分類は決定論の規則で行い、規則ごとに単体テストを置く。分類の規則を変えたら記録の版を上げる。
- [ ] 記録は検索の応答を遅らせない（記録の失敗は検索に影響しない）。
- [ ] 集計は件数と割合だけで、分類×結末の表と、適合度の区間ごとの先頭選択率、別名の提案の受け入れ率を出す。
- [ ] 記録の有無で、検索結果の順位・候補の有無が変わらないことを、同じ入力で比較するテストで確認する。
- [ ] 設計文書§7の判断基準を、観測の開始前にこのIssueへ転記し、結果を見てから変更しない。

### Validation plan

分類・記録・集計は、拡張機能ホストなしの単体テストで試験する。セッションの入口（開始・終了・選択の検知）は、拡張機能ホストのE2Eで、候補を選ぶ・閉じる・入力を直すの各経路を確認する。実利用の観測は、複数の利用者が一定期間使い、集計を持ち寄る。件数が100に満たない間は、傾向を断定しない。

- **実装済み（2026-10-08）:** `src/search/observation/`（分類・記録・保存・集計）、`src/dx/searchObservation.ts`、検索画面への接続、設定`search.observation.enabled`・`includeText`、コマンド2件。テストは`test/searchObservation.test.ts`（8件）と`test/extensionIntegration.test.ts`の固定。受入条件のうち、記録の有無で検索結果が変わらないこと（記録は結果を読むだけ）と、既定の記録に依頼文・表名が入らないことは単体テストで確認した。
- **敵対的レビュー（2026-10-08、workflow、指摘6件を検証・すべて再現）と修正:** 確定した指摘は次のとおり修正した。(1) 読み込みの失敗を「空」と扱い、1000件を1件で上書きする欠陥（読み込みは ENOENT のみ空とし、それ以外は失敗として返す）。(2) 設定を切っても既存の行に残る依頼文（書き込み時に依頼文を取り除く）。(3) 構造による近い候補が説明として数えられない欠陥、および近い候補があるのに no-such-table とする欠陥。(4) 英字の語が表名の一部として一致する誤り（語の単位で照合）。(5) 消去の失敗が成功と表示される欠陥。加えて、書き込みの直列化、fsync、`.tmp` の消去、max=1 の境界、近い候補の選択を適合度の較正から外すこと、判定できなかった件数の分離。テストは `test/searchObservation.test.ts` の15件。
- **拡張機能ホストでの確認（自動）:** `test/e2e/suite/extensionHost.test.ts` に `search-observation-recording` ステージを追加した。設定を入れて2回検索すると、2行が記録される（分類 found と unsupported-op、結末 picked-candidate と cancelled）。既定では依頼文・表名が保存されない。全ステージ成功（WSLg の表示 `:0` で実行、xvfb は不要）。
- **全体テスト:** 土台 `66b2d9c` と失敗の集合が一致（44件、すべて土台にも既存。新規の失敗なし）。
- 残り: 画面操作の目視（検索画面で、選ぶ・閉じる・入力を直す・別名の登録の各経路。初回の案内の文面。集計の表示。消去の確認ダイアログ）。E2E は入口を scripted search に限るため、検索画面の実際の操作は人が確かめる必要がある。ネットワークを使うコードを含まないことは、`src/search/observation/` と `src/dx/searchObservation.ts` に送信の経路がないことを読んで確認した。
- 未対応（レビューで低優先・判断が要るもの）: 「入力を直した後に選んだ」は、検索のたびに数えるため、入力の細かい修正も含む。設計どおりとしたが、集計の読み方に注意が要る。既知の語は近い候補の表名だけから集めるため、索引にある別の表の名前と一致する英字の語は、近い候補に入らない限り未知と判定されうる。
- 設定のうち`includeText`は、利用者がローカルでの見直しのためにオンにする場合の注意文を決める。
