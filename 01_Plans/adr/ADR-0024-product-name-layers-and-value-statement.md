# ADR-0024: 製品の総称と、記法・契約の名であるMMIを分ける

- Status: Proposed
- Date: 2026-10-17
- Deciders: Human Sponsor（採否と総称の選定）、MMI Lead Agent（起案）
- Scope: 製品の総称、MMI Notation・CLI・公開契約・識別子の名前、外向けの価値の説明
- Related: [ADR-0012](ADR-0012-mission-redefinition-notation-as-governance-boundary.md)（記法）、[ADR-0019](ADR-0019-ai-era-sier-document-value-and-policy.md) D1・D10・D13（価値と優先度の正本）、[磨き直しの足掛かり](../product-repolish-plan.md)、[#504](https://github.com/hat47x/markdown-matrix-injector/issues/504)

## Context (背景と課題)

製品名のMarkdown Matrix Injectorは、2026年3月の初版の役割を表している。MarkdownのプレビューへMatrix（表）をInjectする道具である。製品定義はその後、ADR-0012でガバナンス境界へ、ADR-0019でモダナイズ基盤へ、ADR-0019の改訂（D0・D13）で併用執筆を支える読み取り専用の橋へと、7か月で3回書き換えられた。今の役割は、表だけを扱うものでも、差し込むだけのものでもない。

外向けの説明には、三つの時期の定義が混ざっている。表示名と導入手順は表の参照を、概要とpackage.jsonはADR-0012のガバナンス境界を、READMEの冒頭はADR-0019の橋を説明する。

一方で、MMIの名は記法と契約に深く入っている。研究層を除く製品コードには、`MMI_*`の診断コードが100種以上、`mmi.*`の公開契約が約30種ある。`mmi`コマンド、MMI Notation v1、文書に残す印（`mmi:extracted`等）、`mmi-ledger.json`もこの名を使う。記法の診断は安定API（P6）である。

VS Code拡張とnpmパッケージは、2026-10-17時点で未公開である。拡張IDとパッケージ名を利用者への影響なく変えられるのは、初回公開の前に限られる。

検討した方式は三つある。方式AはMMIを固有名として残し、展開形を退役させる。方式Bは総称を新しく立て、MMIを記法・契約・CLIの名として残す。方式Cはすべてを改名する。比較と候補の調査は、[磨き直しの足掛かり](../product-repolish-plan.md)の第4節にまとめた。

## Decision (決定事項)

### D1. 名前を二つの層に分ける

人が呼ぶ製品の総称と、記法・契約・CLIの名であるMMIを分ける（方式B）。総称は製品の役割を伝える。MMIは、記法とそれを扱う道具の名として残す。

### D2. MMIの層は変えない

総称を変えても、次のものは変えない。

- 記法の構文`![[...]]`、パラメータ、変換順序、`x-`の実験キー
- `MMI_*`診断コードの意味
- 版付きの`mmi.*`契約名と、各版の内容
- 文書に残す印とファイル名（`mmi:extracted`、`mmi-ledger.json`、`mmi-assets/`等）
- `mmi`コマンドと既存のオプション、`skills/mmi`

### D3. 総称を新しく立て、作者の製品群の命名に揃える

作者の製品群（SEI Cognition＝井、TEI＝鼎、EKI Fabric＝益、SUI Sensemaking＝萃）は、易経の卦の一字をローマ字3文字で書き、英語の一般名を添える。本製品もこの流儀に揃え、第46卦「升」（地風升）から採った升（SHO Bridge）を第一候補とする。升は萃（SUI）の次の卦で、序卦伝は「集まったものが昇るのが升」と説く。小を積んで高大に至り、時に従って柔らかく昇る卦の像は、情報単位ごとに少しずつ移し、移す範囲と速さを人が決める方針（ADR-0019 D2・D13）に重なる。升は方眼紙の升目の字でもある。検討の詳細と外した卦は[磨き直しの足掛かり](../product-repolish-plan.md)の4.4〜4.6にある。

2026-10-24の予備調査では、J-PlatPatとWIPO Global Brand Databaseに同一の商標は無かった。第42類に読みの近いジョブリッジ（JOBRIDGE）等があり、出所の混同のおそれは弁理士に確かめる（[磨き直しの足掛かり](../product-repolish-plan.md)の4.6a）。弁理士の確認と、SIerの書き手に見本を読んでもらう確認を経て、Human Sponsorが決める。外れた場合は、同じ流儀の別の卦を選び直すか、方式AでMMIを固有名として残す。2026-10-17の案（Tsugite・Genpon）は、製品群の流儀に沿わないため取り下げる。

### D4. 識別子は総称に依存させない

VS Codeのコマンドと設定の識別子は、総称ではなく`mmi.*`へ寄せる。旧キー（`markdownMatrixInjector.*`）の値は読み続け、旧コマンドIDも移行期間のあいだ別名として残す。拡張IDとnpmパッケージ名は総称と同時に決め、初回公開の前に移す。役割がまた変わっても、総称の変更を表示名と文書だけで済ませるためである。

### D5. 外向けの価値の説明を一つにする

外向けの説明は、次の一文の定義と四つの約束に揃える。これはADR-0019 D1の言い換えであり、価値の正本はADR-0019のままとする。

> 本製品は、人が慣れた道具で書き続ける原本と、Markdown・AI・CIとのあいだに架ける読み取り専用の橋である。原本には手を加えず、取り出した内容には出典を付ける。どの情報をどこまで移すかは人が決める。

| 約束 | 意味 | 支える決定 |
| --- | --- | --- |
| 書き手を止めない | 慣れた道具と書式のまま書ける。候補の採否や形式の統一を、書き始める条件にしない | ADR-0019 D13 |
| 原本に手を加えない | どの過程でも原本を書き換えず、許された範囲だけを読む | ADR-0019 D12 |
| 出典と鮮度を確かめられる | どこから何を得たか、今も同じかを確かめられる。原本の事実と推定を分けて示す | ADR-0019 D6・D8・D12 |
| いつでも離れられる | 決めた範囲を標準の形式へ実体化し、原本やMMIを外しても成り立つかを検査できる | ADR-0019 D2・D3 |

契約上の値であるLinked・Extracted・Detachedは変えない。利用者向けの文書と画面では、「つないで書く」「取り込む」「切り離す」を併記する。

### D6. 期限

総称と識別子は、VS Code Marketplaceとnpmへの初回公開の前に決める。決めるまでは、リポジトリ名・パッケージ名・CLI名を変えない。これは#504の条件を引き継ぐ。

## Consequences (結果と影響)

- **Good:** 名前が現在の役割を伝え、表を差し込む道具だという誤解が減る。
- **Good:** 記法・診断コード・公開契約・CLIの互換を保てる。MMI Notationは、国外の実装者にも中立な記法の名として残る。
- **Good:** 識別子が総称から独立するため、役割が再び変わっても、総称の変更は表示名と文書で済む。
- **Bad:** 総称とMMIの二つの名を説明する手間がかかる。たとえば「SHO BridgeはMMI Notationの参照実装」と書き添える場面が増える。
- **Bad:** VS Codeのコマンドと設定の移行と、旧キーを読む互換処理が要る。
- **Bad:** 商標調査と読み手の確認に時間がかかり、初回公開はその後になる。

## 採択後の作業

1. 総称を決め、本ADRに記録する。
2. README、概要、package.json、walkthrough、利用マニュアル、CHANGELOGを、D5の定義と約束で書き直し、版を上げる。
3. 拡張ID、npm名、コマンドと設定の識別子を移し、旧キーの読み取りを回帰テストで固定する。
4. AGENTS.mdと製品要求の冒頭を、新しい総称で書き直す。意味は変えない。
5. リポジトリ名を変え、文書中の絶対URLを書き換える。
