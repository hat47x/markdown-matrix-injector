# ADR-0023: 表の探索では、言い換えよりあいまい検索（略語・表記ゆれ）を先に強め、モデル実行環境は単独の用途では導入しない

- Status: Proposed
- Date: 2026-10-07
- Deciders: Human Sponsor（採否）、MMI Lead Agent（起案）
- Scope: CPUでの範囲探索（[issue-0115](../issues/issue-0115-cpu-range-search.md)）、ローカル認知runtime（[issue-0113](../issues/issue-0113-local-ai-feasibility.md)）、仮説カードK5
- Related: [ADR-0018](ADR-0018-cognitive-assistance-plane.md)、[ADR-0020](ADR-0020-requirement-oriented-cognition-method-selection.md)、[設計](../../02_Architecture/input-assistance-cpu-search.md)

## Context

表の探索で、依頼の言い換えをモデルで扱うかが論点になった。Human Sponsorは次の二点を指摘した。

1. 言い換え検索のために、利用者へOllama等を導入してもらう動機は弱い。
2. 言い換え検索の需要が高いかは疑わしい。あいまい検索のほうが需要はありそうである。

実測は、この指摘と矛盾しない。未見セットv4・v5の初回評価（決定論の方式、いずれも1回・結果は固定）で、カテゴリ別の再現率は次のとおりだった。

| カテゴリ | v4 | v5 | 読み取れること |
| --- | --- | --- | --- |
| 名前どおり（exact） | 8/8 | 8/8 | 足りている |
| 誤字・表記ゆれ（typo） | 4/4 | 4/4 | 足りている |
| 重複（duplicate） | 2/4 | 6/6 | 概ね足りている |
| 略語（abbreviation） | 4/6 | 2/6 | 不足。失敗の型は下記 |
| 言い換え（paraphrase） | 1/8 | 0/22 | 語の一致と概念表では届かない |

棄却精度1.000・自動確定0は、どの回でも保たれた。

略語の失敗は、すべて英字の頭字語と日本語の正式名称のずれである（NFRと非機能要件、CRと変更要求、RBACと権限・ロール、BKUPとバックアップなど）。これは意味の理解ではなく、略語と正式名称の対応という有限で公開された語彙の問題であり、モデルなしで扱える。一方、言い換えの失敗は、話題語が表名に無い語彙の問題（予行演習とリハーサル、打合せと会議）で、辞書では網羅できない。

言い換えの需要は、まだ観測がない。評価セットは開発側が作った依頼文であり、利用者が実際にどの程度、表名を知らずに説明で探すかは分かっていない。

## 検討した選択肢

A. 言い換えを、オプションのローカルモデル（M2の埋め込み、M3のbounded Judgment）で扱う方向を進める。
- 良い点: 語彙の問題に届く可能性がある。
- 悪い点: 需要が未観測である。導入先の環境にruntimeとモデルが要る。単独の用途では、導入の手間に見合わない。

B. 言い換えは現状の決定論的な補助にとどめ、略語と表記ゆれを先に強める。モデルの扱いは、複数の用途で需要が示された場合に改めて判断する。
- 良い点: 需要が高そうな部分から、MMIの既定（CPUのみ・GPU/LLM不要）のまま改善できる。測定と撤回が容易である。
- 悪い点: 言い換えの水準は上がらない。

C. 言い換えを捨て、関連する実装を撤回する。
- 悪い点: 需要が未観測のまま機能を消すのは早い。決定論的な補助の安全性は保たれている。

## Decision（提案）

Bを採る。

1. **略語を先に扱う。** 決定論（M0・M1）で、次の三層の語彙を使う。
   - 同梱の略語集: IT・業務で広く使われる略語と正式名称の対応。出典と版を記録し、一覧として公開する。特定の評価セットから作らない。
   - 利用者の語彙: ブックやワークスペースにある略語表（見出しが略語と正式名称の対応になっている表）と設定で与えた対応。MMI自身が表Candidateとして見つけられる。
   - 規則的な短縮: 全角半角・大文字小文字・記号（N/WとNW）・語頭の頭字語。
   略語から得た候補は`inferred`のまま、使った対応を理由として示す。自動確定はしない。
2. **言い換えは、現状の決定論的な補助と、既定オフの実験的な埋め込み経路のまま据え置く。** 拡張せず、評価の対象を増やさない。需要の観測を待つ。
3. **モデルの実行環境は、単独の用途のために導入させない。** 導入を検討する条件は次の三つがすべて満たされたときとする。
   - M0〜M2で足りない具体的なタスクが、検索の言い換えに加えて、少なくとも別に一種類記録されている（例: 取り込み候補の役割判定、書式差の説明）。
   - 利用者が、すでに実行環境を持っている。MMIはインストールも取得もしない。
   - 新しい未見セットで、決定論の方式に対する改善が測定されている。
4. **需要を測る。** 検索で候補が出なかった依頼を、利用者の同意のもとローカルに分類して数える仕組みを、観測のために設ける（略語・表記・言い換え・該当なし）。外部へ送らない。この観測で言い換えの割合が小さければ、2を維持する。
5. **評価の規律を保つ。** 略語の改善は、評価セットv6（60件、凍結済み）で1回だけ測る。v6は、コーパスの目録だけを見た独立の作成者が書き、実装者は文面を読んでいない。v6の失敗文へ略語集・規則を合わせ込まない。結果は消費済みとして記録する。略語集を入れる前の実装でv6を1回測って基準値とし、その失敗の一覧は、略語集を作る材料に使わない（略語集は、公開された一般の語彙から作る）。

## 判定条件

次のいずれかが成り立つ場合、Bの略語の改善は効果がないと判断し、撤回する。

- v6の略語カテゴリの再現率が、改善前の実装で測った値（v6を同じ条件で測った基準値）を、有意に上回らない。目安は、基準値に対して少なくとも+0.25（16件で4件）。
- 棄却精度が1.000を下回る、または自動確定が1件でも出る。
- 同梱の略語集が、それ以外のカテゴリの順位を悪化させる。

## Consequences

- **Good:** 需要がありそうな部分を、決定論のまま、MMIの既定の範囲で強められる。モデル導入の判断を、観測と複数の用途に結び付けて先送りできる。略語集と利用者語彙は、AI・CLI経由の入力支援（K6）にも使える。
- **Bad:** 言い換えの水準は当面上がらない。略語集の保守（追加・出典・版）が要る。利用者語彙の読取りは、新しい入力経路になる。需要の観測の仕組みは、同意と保存先の設計が要る。
