# ADR-0017: ハエ脳由来の疎表現を用いる書式逸脱支援の境界

- Status: Accepted
- Date: 2026-09-12
- Related: requirements.md Phase 1 / Phase 5 / Phase 11、ADR-0012、ADR-0016

## 背景

規則的に定義されたExcel設計書は、まず書式定義を確定し、その定義に従って決定論的に読み取るのがMMIの正本保護・検証可能性と整合する。一方、既知書式の軽微な崩れや、どの書式に近いかの候補抽出には、完全一致だけでは扱いにくい余地がある。

ここで必要なのは、セルの意味を生成する汎用AIではなく、書式上の特徴から既知パターン候補と逸脱度を返し、未知なら未知として止まる軽量な認知補助である。過去検討で、ショウジョウバエ嗅覚系などに着想を得た疎な高次元表現、競合（winner-take-all）、novelty検出を候補抽出へ限定利用する方針を採った。

## 決定

1. **通常経路は決定論的なまま維持する。** 目標構成は `Format Definition -> Deterministic Parser -> Structured IR` とし、ハエ脳由来の仕組みを通常のパース、意味生成、描画へ混入させない。
2. ハエ脳由来の層は、`format feature -> sparse projection -> candidate ranking -> WTA/novelty -> DeviationScore` の**助言専用**とする。出力は候補、confidence、DeviationScoreまでであり、正本・書式定義・Markdownを自動変更しない。
3. 最初の実装はCPU-only、純粋関数、外部依存なし、ネットワークなしとする。実在コネクトームの全脳シミュレーションやSNN実装は行わず、FlyHash風の疎表現と競合・未知検出という計算上の性質だけを利用する。
4. 同じ入力は必ず同じ結果を返す。乱数、学習状態、時刻、外部サービスに結果を依存させない。
5. 既知候補が弱い場合は `novel`、上位候補が拮抗する場合は `ambiguous` として止める。近い候補があることを「正しい書式」と読み替えない。
6. 第一段階では抽象化済みの書式特徴トークンだけを扱い、既存 `workbookLoader` には接続しない。Excelのスタイル・結合・罫線・位置情報を特徴化するadapterは、評価結果を確認した後の別Issueとする。
7. 製品経路へ接続する前に、既知書式、軽微な逸脱、別書式、未知書式のfixtureで誤採用率と候補順位を測定する。候補を出せても自動適用は行わない。

## 受け入れるトレードオフ

第一段階は書式特徴の抽出自体を実装しないため、直ちにExcel方眼紙を自動解析する機能にはならない。その代わり、既存MMIの決定論的挙動とRead-only境界を一切変えず、疎表現・WTA・noveltyが候補抽出に有効かだけを独立に検証できる。

「ハエ脳由来」は生物学的忠実再現を意味しない。採用判断は由来の面白さではなく、CPUコスト、再現性、誤採用率、説明可能なDeviationScoreが実務上有効かで行う。

## 状態と実行

最初のアトミック実装は `issue-0114-fly-inspired-sparse-format-matcher.md` で行う。製品経路への統合、Excelスタイル特徴抽出、書式定義の自動生成は本ADRだけでは承認しない。
