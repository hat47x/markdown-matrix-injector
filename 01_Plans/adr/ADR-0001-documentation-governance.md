# ADR-0001: Public documentation governance

- Status: Accepted
- Date: 2026-03-21
- Deciders: Project Maintainers
- Scope: `01_Plans/`, `02_Architecture/`, `04_Documentation/`

## Context (背景と課題)
- `04_Documentation/` は利用者や導入担当者が参照する公開文書を置く想定だが、どこまでを公開文書として扱うか、どの品質で公開するかの判断基準が明文化されていない。
- 一方で、AIエージェント向け運用メモや計画トリアージ手順は内部文書であり、公開文書と混在すると読者と保守責務が曖昧になる。

## Decision (決定事項)
- `04_Documentation/` には、ユーザーガイド、導入手順、運用手順、公開可能な検証手順などの対外公開文書のみを格納する。
- `04_Documentation/` の文書はGist等での個別公開を前提とし、アプリケーションのCIアーティファクトやrelease bundleには含めない。
- 開発プロジェクトの内部文書は、原則として以下に分離する。
  - 計画・運用・タスク再開手順: `01_Plans/`は次のとおりです。
  - 設計・責務分離・技術方針: `02_Architecture/`
- 公開文書の執筆ルールは次の5点とする。
  1. 読者を明示する。
  2. 内部用語や未確定方針を書かない。
  3. 手順書は前提条件・コマンド・期待結果をセットで記述する。
  4. パス、画面名、コマンドを再現可能な粒度で書く。
  5. 詳細が別文書にある場合は正本へのリンクを明示する。
- 公開前レビューでは、少なくとも次を確認する。
  - 対外公開して問題ない内容だけで構成されていること。
  - 実際の手順で再現できること。
  - 内部専用情報や内部ツール依存の説明が残っていないこと。

## Consequences (結果と影響)
- **Good:** 公開文書と内部文書の責務が明確になり、利用者向け文書の可読性とレビュー観点が安定する。
- **Good:** 公開文書の公開経路とアプリケーション配布物が分離され、リリース成果物を最小限に保てる。
- **Good:** AI エージェント向け運用メモを計画文書側へ集約でき、公開文書に内部事情が混ざりにくくなる。
- **Bad:** 文書追加時に、公開文書か内部文書かの配置判断を先に行う必要がある。
- **Bad:** Gist 公開時の同期漏れを防ぐため、公開文書の運用フローを継続的に管理する必要がある。
- **Bad:** 既存文書も必要に応じて配置や表現を継続的に見直す必要がある。
