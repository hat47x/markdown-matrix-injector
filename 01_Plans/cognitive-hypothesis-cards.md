# 認知機能の仮説カード

[ADR-0019](adr/ADR-0019-ai-era-sier-document-value-and-policy.md) D9の形式で、認知補助（[ADR-0018](adr/ADR-0018-cognitive-assistance-plane.md)）の各機能を製品価値の観点から比べる。ADR-0019はProposedであり、本書の「判断」は採否ではなく次の一手の提案である。

証拠の段階は、実装済み・自動テスト済み・実機確認済み・利用者による価値確認済みを区別する（[作業ルール](../00_Prompt/system_prompt.md)）。

## K1 取り込み候補

1. **成果物・利用者・経路**: 既存のExcel設計書（方眼紙を含む）をMarkdownへ移す担当者。経路B。表候補は経路Aの`inspect`にも使える。
2. **起きている失敗**: 方眼紙の表は、現行の表検出と素直な参照では見出しを認識できず（4/14）、別紙になる（10/14）。正本どおりに描けたのは3/12。見出し枠・文章・押印欄も表と区別されずに範囲候補になる（20/43）。手で`columns=`の相対列と`mode=table`を書くのは現実的でない。
3. **解決方法**: 結合の起点列から論理列を求め、記法を変えずに`columns=`・`header=first`・必要なら`mode=table`を提案する。提案は実際の描画で再検証する。表以外の領域は役割の候補として並べ、人が本文へ移すか決める（[設計](../02_Architecture/import-assistance.md)）。既存の手段（補完・案内付きの作成）は範囲の候補を出すが、方眼紙の表を表として描く指定は作れない。
4. **境界との整合**: 決定論・ローカル・読み取りのみ。提案は描画で確かめたものだけ。見えなくなる値は番地付きで示す。下書きは利用者が保存先を選ぶ新しいファイル。
5. **測り方**: 架空データの評価（済）。実在の設計書で、候補を採用・修正・却下した割合と理由、取り込み範囲を決めるまでの時間を記録する。
6. **効果がないと判断する条件**: 実在の設計書で、表の候補の半分以上が修正か却下になる。または、下書きを使うより手で参照を書くほうが速いと観測される。
- **現在の証拠**: 開発用データで12/12、追加ケースの1回目で3/9（修正後9/9、盲検ではない）。どの回も消えた値0件。VS Code 1.134.0の拡張機能ホストで、下書きの参照14件がすべて表として描画され、原本は不変だった。

## K2 書式のまとまり

1. **成果物・利用者・経路**: 同じ雛形から作られた多数のシート（画面定義書、テーブル定義書）を取り込む担当者とレビュアー。経路B。
2. **起きている失敗**: シートごとに同じ判断を繰り返す。雛形から外れたシート（列の追加など）が埋もれる。
3. **解決方法**: 見出し・表の列名・枠のラベルが一致するシートをまとめ、近い書式との差を「表『2. 画面項目』に列『初期値』があります」のように示す。これはADR-0017の書式研究の製品形で、一致と差分の列挙だけで説明できる。Fly-inspired matcherは、完全一致では拾えない「少しずつ違う」シートが多い場合の候補として残す。
4. **境界との整合**: 候補であり、判断を代替しない。割合は並べ替えにだけ使う。学習状態を持たない（ADR-0018 D6）。
5. **測り方**: 同じ書式のまとまりごとに判断した回数と、シートごとに判断した回数の比較。差を示したシートで実際に確認が必要だった割合。
6. **効果がないと判断する条件**: 実在のブックで同じ書式のシートが少なく（例: まとまりの平均が3シート未満）、判断回数が減らない。または差の表示が確認に結び付かない。
- **現在の証拠**: 架空データで、同じ書式の2組と、列が1つ多いシートの差を正しく示した。価値は未測定。

## K3 レビュー経路

1. **成果物・利用者・経路**: 取り込んだシートをレビューする人。経路B。
2. **起きている失敗（仮説）**: どのシートを注意して見るべきかが分からず、注意が均等に配られる。
3. **解決方法（研究層）**: 書式照合の結果（matched / ambiguous / novel）を、閉集合の判断（inspect / routine）へ写す。Jev等のproviderは輸送を注入する形で用意されているが、製品の経路はない。
4. **境界との整合**: 研究層で担保済み（承認・適用の権限なし、外部送信は明示同意）。
5. **測り方**: ADR-0019 D9の「注意が必要と示した箇所で、実際に指摘が見つかった割合」。比較対象は決定論の規則（K1の注意やK2の差があるシートを要確認とする）。
6. **効果がないと判断する条件**: 決定論の規則と同等以下。
- **現在の証拠**: 利用者の観測はない。providerへ渡す状態（分類・候補数・新規度）はすでに決定論で求まっており、閉集合モデルが上乗せできる情報は小さい見込みである。評価記録・比較・コーデックの基盤（issue-0167〜0191）は整ったが、評価に使う実データと製品の経路がない。`main`の研究層の単体テストには、改行を保った取得でも失敗が26件ある。
- **提案**: 評価基盤の拡張を止める。K1・K2の実機観測で、注意と差分の表示が実際の指摘にどれだけ当たるかを先に測り、決定論の規則で足りない箇所が見つかった場合にだけ比較を再開する。

## K4 表らしさ判定

1. **成果物・利用者・経路**: 領域が表かどうかの判定。K1の役割と、経路Aの目録。
2. **起きている失敗**: 見出し枠・連絡先カード・箇条書きが表として扱われる。
3. **解決方法（研究層）**: 製品に依存しない観測の形式を定め、規則・ロジスティック回帰・LightGBMを比べる準備（SAI-1）が進んでいる。
4. **境界との整合**: 研究専用。製品へは未接続。
5. **測り方**: K1と同じ領域で、役割の正しさを規則と比べる。
6. **効果がないと判断する条件**: 実在の設計書でK1の規則を上回らない。
- **現在の証拠**: 研究の信号（見出し候補の下に数値の列があるか）は、方眼紙の領域で表12/14・表でない領域0/20（開発用）、表8/10・表でない領域1/4（追加）だった。数値の列がない表を落とし、領域の切り分けと見出し・論理列は出さない。取り込みに必要なのは後者である。
- **提案**: SAI-1の比較題材に、K1の追加ケースで見つかった失敗の型（長い見出し枠、接尾辞のないラベル、ラベル風の値が並ぶ表、表直下の注記、背の高い見出し、表内の空行）を加える。製品への接続は、実在の設計書でK1の規則を上回ってから判断する。

## K6 目録と意味による選択

1. **成果物・利用者・経路**:
   - 経路B: 設計書を書く人（VS Codeの表の目録）。
   - 経路A: AIエージェントとCI（`mmi`のCLI）。
2. **起きている失敗**:
   - 表・列・行を選ぶためにExcelを開いて座標を調べる。
   - AIは巨大な正本を丸読みするか、座標を推測する。
   - `columns=`の相対列は人にもAIにも間違えやすい。
3. **解決方法**:
   - ブック自身の宣言（Excelテーブル・名前）と表の候補から目録を作る。
   - 表を名前で、列を見出しで、行を文字列や件数で選ぶ。
   - 記法v1へ写し、描画で確かめる。
   - 記法で正確に表せない絞り込み（`grep`は表示するどの列にも当たる）は、件数付きで知らせる（[設計](../02_Architecture/table-navigation.md)）。
   - 入力支援と診断を、CLIのJSON出力と終了コードでAIにも開く。
4. **境界との整合**:
   - 読み取りのみ。提案は描画で確かめる。
   - 目録は既定で構造だけを返し、値は明示したときだけ返す。
   - 記法は変えない。変えるかは[ADR-0020](adr/ADR-0020-semantic-selection-in-notation.md)で判断する。
5. **測り方**:
   - AIエージェントが手引きと`mmi`だけで参照付きの章を書き、`check`が0件になるまでの往復数（ADR-0019 D10の指標3）。
   - 人が目録から選ぶ時間と、Excelを開いて座標を調べる時間。
6. **効果がないと判断する条件**:
   - AIが目録を使わずに正本を丸読みする、または`select`の誤りを直せない。
   - 人が目録を使わずにExcelを開き続ける。
- **現在の証拠**:
  - Excelで作ったブックで、名前・テーブル・非表示を読めた。
  - 選択は単体テストと拡張機能ホストで確認した。
  - CLIで`select`→`check`→`render`の流れが通った（開発者による試行）。
  - AIエージェント・利用者での確認はない。

## K5 説明から表を探す

1. **成果物・利用者・経路**: 表の名前や列で参照を探す執筆者。経路B（製品）。
2. **起きている失敗**: 言い換えに弱い（未見v3のRecall@5で0.500、[issue-0115](issues/issue-0115-cpu-range-search.md)）。方眼紙のブックでは、候補が見出しなし・別紙の参照になる（K1と同じ原因）。
3. **解決方法**: 方眼紙の領域にはK1の表候補（論理列・見出し・再検証済みの参照）を使う。言い換えは限定文法と辞書の範囲を見直す（LLMへは切り替えない）。
4. **境界との整合**: 既存の設計どおり。
5. **測り方**: 方眼紙を含む新しい未見セットでのRecall@5と、確認段で表として描けた割合。
6. **効果がないと判断する条件**: 方眼紙のブックで、確認段の表示が別紙のままになる。
- **現在の証拠**: 方眼紙の架空データで、検索の1位が期待どおりの表になった依頼が2/7から5/7（候補5件内は2/7から6/7）になった。方眼紙のない既存の評価は同値。残る失敗は順位と「表題と同じ列名」の読み方で、言い換えとあわせて新しい未見セットで測る。

## 共通の注意

- 開発用データでの満点は根拠にならない。K1では追加ケースの1回目で3/9に落ちた。改善は、作り手の違う未見データか、実在の文書で測る。
- 認知補助の成否は、描画・診断・準拠の結果を変えない（ADR-0018 D1）。どのカードでも、提案は既存の検証を通してから人に示す。
