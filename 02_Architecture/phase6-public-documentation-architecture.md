# 利用文書の設計

利用者が目的に合う文書を選べる構成にする。読書順を強制しない。

- 概要: 何ができ、どの仕事に使えるか。
- チュートリアル: 前提、操作、期待する画面を再現できる手順。
- マニュアル・リファレンス: 操作と制約の逆引き。
- サンプル: 架空の元データと、それを参照する実用的な文書。
- 開発文書: コードの責務、検証コマンド、実機確認の範囲。

公開前に、リンク、サンプル記法、期待結果、対応環境を確認する。画面・動画は実際の操作と対応させ、図解を実機証拠と混同しない。未実装機能や未測定性能を利用できる機能として説明しない。

不具合や仕様の曖昧さが見つかった場合は、該当する仕様・コード・テストまたはIssueを更新する。定型監査票、KPI、全段階の承認をすべての文書変更に要求しない。
