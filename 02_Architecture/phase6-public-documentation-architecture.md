# 利用文書の設計

利用者が目的に応じて必要な文書を選べる構成とし、読む順序は強制しない。

- 概要: 何ができ、どの仕事に使えるか。
- チュートリアル: 前提、操作、期待する画面を再現できる手順。
- マニュアル・リファレンス: 操作と制約の逆引き。
- サンプル: 架空の元データと、それを参照する実用的な文書。
- 開発文書: コードの責務、検証コマンド、実機確認の範囲。

公開前には、リンク、サンプル記法、期待結果、対応環境を確認する。画面や動画は実際の操作と対応させ、説明用の図解を実機で確認した証拠と混同しない。未実装の機能や未測定の性能を、利用可能・実証済みであるかのように説明しない。

不具合や仕様の曖昧な箇所が見つかった場合は、該当する仕様・コード・テストまたはIssueを更新する。一方、すべての文書変更について、定型監査票、KPI、全段階での承認を一律に必須とはしない。

利用者向けの入口は[利用文書一覧](../04_Documentation/README.md)とする。
