# 表の検索の需要観測（設計）

- 状態: 実装中（分類・privacy-safe record・workspace-local store・集計・検索セッション接続まで。2026-10-08）
- 関連: [ADR-0023](../01_Plans/adr/ADR-0023-fuzzy-search-before-paraphrase-and-model-runtime.md)、[issue-0207](../01_Plans/issues/issue-0207-search-demand-observation.md)、[CPUでの範囲探索](input-assistance-cpu-search.md)（§2.1の保存規約）、[認知機能の仮説カード](../01_Plans/cognitive-hypothesis-cards.md)（K5）

## 1. 何を知りたいか

ADR-0023は、言い換え検索（表名にない言葉で説明して探す）の需要が未観測であることを理由に、モデルの実行環境を導入しないと決めた。需要が分かれば、その判断を見直せる。そこで、利用者が実際に表を探したとき、「探して見つからなかった」依頼がどの種類の依頼だったかを数える。

知りたいことは次の四つである。

1. 見つからなかった依頼のうち、略語・表記ゆれ・言い換え・該当なし・未対応の操作が、それぞれどれだけか。
2. 利用者は結局どうしたか（近い候補を選んだ、入力を直して見つけた、あきらめた）。
3. 適合度の目安は、利用者の選択と合っているか（先頭の候補を選んだか、適合度が高い候補ほど選ばれたか）。
4. 別名の登録の提案は、受け入れられているか。

評価セットは開発側が作った依頼文であり、実際の分布を表さない。この観測は、評価セットの配分（略語・言い換えなどの比率）を現実に合わせるためにも使う。

## 2. 守る境界

- 既定はオフ。設定 `markdownMatrixInjector.search.observation.enabled` をtrueにしたときだけ記録する。有効にする操作は利用者が行い、最初に何を記録するかを一度だけ示す。
- 依頼文は記録しない。依頼文には、機密の表名や社名が含まれうる。既定では、依頼の特徴（分類、語数、英字の語の数）だけを記録する。依頼文そのものの保存は、別の設定 `search.observation.includeText`（既定false）で、利用者がローカルでの見直し用に明示的にオンにしたときだけ行う。
- 外部へ送らない。保存先はワークスペース単位のローカル領域（VS Codeの `storageUri`）で、リポジトリ内には置かない。自動送信の経路は作らない。
- 消せる。コマンドで記録を表示・書き出し・消去できる。消去すると、保存先のファイルを削除する。
- 件数に上限を置く。1,000件の循環とし、古い記録から消す。
- 判断に使わない。記録は、需要の観測と適合度の較正のためだけに使う。検索結果の順位や、候補を出すかどうかは、記録によって変えない。
- 組織の利用状況の監視にしない。記録は個人のワークスペースの中にとどまり、集計して共有するのは利用者自身である（§6）。利用者名・ファイル名・表名は記録しない。

## 3. 何を記録するか

検索の一回（検索画面を開いてから、選ぶ・閉じるまで）を一つのセッションとし、セッションごとに一件を記録する。

```json
{
  "schema": "mmi.search-observation/v1",
  "at": "2026-10-08",
  "queries": 3,
  "final": { "status": "no-match", "class": "abbreviation", "tokens": 4, "latinWords": 1, "question": false },
  "outcome": "picked-near-miss",
  "picked": { "rank": 1, "fit": 0.4, "basis": "name" },
  "alias": "offered-accepted",
  "ms": 8200
}
```

| 項目 | 内容 | 備考 |
| --- | --- | --- |
| at | 日付だけ | 時刻は残さない |
| queries | セッション中に検索を実行した回数 | 入力を直した回数の目安 |
| final.status | 最後の検索の状態（candidates / no-match / unsupported / needs-more-input） | |
| final.class | 最後の依頼の分類（§4） | |
| final.tokens / latinWords | 語数、英字の語の数 | 依頼文は含まない |
| final.question | 疑問文の形か | |
| outcome | 結末（§5） | |
| picked | 選んだ候補の順位・適合度・見つけ方 | 選んだ場合のみ。表の名前は含まない |
| alias | 別名の登録の提案の結果（none / offered-declined / offered-accepted） | |
| ms | 検索画面を開いていた時間 | |

includeText をオンにした場合だけ、final.text を追加する。

## 4. 見つからなかった依頼の分類

分類は決定論の規則で行い、依頼の意味をモデルで推定しない。最後の検索の結果から、次の順で判定する。

| 分類 | 判定 |
| --- | --- |
| found | 通常の候補が出た |
| unsupported-op | 集計・比較・並べ替えなど、記法で表せない操作の依頼として棄却された |
| notation | 近い候補が出て、その名前との差が表記（全角半角・長音・送り仮名・誤字）の範囲に収まる |
| abbreviation | 依頼に、どの候補の名前にも無い英字の語が一つだけあり、上の分類に当たらない |
| description | 疑問文・説明の形で、言い換えの経路（構造による候補）が動いた、または動く条件を満たした |
| no-such-table | 上のどれにも当たらず、近い候補も出なかった |
| other | 判定できない |

判定規則と閾値はコードに置き、規則を変えたら、記録の schema の版を上げる。分類は完全ではないので、集計の読み方に誤差を明記する（§6）。

## 5. 結末

| 結末 | 意味 |
| --- | --- |
| picked-candidate | 通常の候補を選んだ |
| picked-near-miss | 「近いかもしれない表」を選んだ |
| picked-after-edit | 入力を直した後に候補を選んだ |
| cancelled | 何も選ばず閉じた |

「final.class が description で、結末が cancelled または picked-near-miss」の割合が、言い換えの需要の一つの目安になる。「abbreviation で picked-near-miss かつ別名を登録した」割合は、略語の層が機能しているかの目安になる。

適合度の較正は、picked.rank と picked.fit で行う。先頭の候補が選ばれた割合を、適合度の区間（0.9以上、0.7〜0.9、0.5〜0.7、それ未満）ごとに集計し、区間が上がるほど先頭が選ばれやすいかを見る。

## 6. 集計と共有

利用者は、コマンド「MMI: 検索の観測を集計する」で、次の集計だけを表示・書き出せる。

- 記録件数と期間。
- 分類別・結末別の件数と割合（分類と結末の組合せ）。
- 適合度の区間ごとの先頭選択率。
- 別名の提案の受け入れ率。

書き出すのは件数だけのMarkdownで、依頼文を含まない。共有するかどうかは利用者が決める。複数人分を合算する場合は、利用者が集計を持ち寄る。MMI側に集める経路は作らない。

## 7. 判断の基準（事前に置く）

結果を見てから基準を動かさないよう、解釈を先に定める。これらは目安であり、数字だけで製品方針を自動的に決めない。

| 条件 | 解釈 | 次の判断 |
| --- | --- | --- |
| 分類が確定した「見つからなかった依頼」が合計100件以上で、3人以上の利用者が含まれる | 判断に足る量 | 下の行を適用する |
| description が10%未満 | 言い換えの需要は小さい | ADR-0023の据え置きを維持する。評価セットの言い換えの配分を下げる |
| description が25%以上 | 言い換えの需要は無視できない | モデルの導入条件（ADR-0023 Decision 3）のうち、「別の用途の記録」を探す。単独では導入しない |
| abbreviation が最多 | 略語の層が主戦場 | 実在の文書での略語の併記・略語表の有無を観測する |
| notation が最多 | 正規化の不足 | 表記ゆれの規則を、新しい未見セットで見直す |
| 先頭選択率が適合度の区間と無関係 | 適合度が当てにならない | 適合度の式を見直すか、表示をやめる |

100件に満たない間は、傾向を断定しない。

## 8. 実装の分担

| 場所 | 責務 |
| --- | --- |
| src/search/observation/classify.ts | 検索結果から分類を決める純粋関数（§4）。単体テストで規則を固定する |
| src/search/observation/record.ts | セッションの記録を組み立てる。依頼文を含めない既定を型で守る |
| src/search/observation/store.ts | ローカルの保存（循環・消去・件数上限）。ファイル操作はここだけ |
| src/search/observation/summary.ts | 集計（§6）。純粋関数 |
| src/dx/searchFlow.ts | セッションの開始・終了を検知して記録を依頼する。記録は検索の応答を待たせない |
| コマンドと設定 | 集計の表示・書き出し・消去。search.observation.* の設定 |

分類・記録・集計は、VS Codeに依存しない純粋な部分に置き、拡張機能ホストなしで試験できるようにする。searchFlow.ts は、セッションの出入口だけを担う。

## 9. この設計で保証しないこと

- 利用者の意図は分からない。見つからなかった理由は、依頼の分類から推定するだけである。
- 少人数・少件数の観測は、一般化できない。
- 記録の有無で利用者の行動が変わる可能性がある（観測されていると知っている）。
