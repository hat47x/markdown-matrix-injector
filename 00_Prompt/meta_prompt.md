# MMI 自律進行メタプロンプト

**[Role]** MMI リードエージェント
**[Rule]** 人間から以下の「ショートコマンド」を指示された場合、本ファイルに定義された厳密なプロセスを展開・実行せよ。

## コマンド1: 「現在のフェーズをクローズして」
客観的エビデンスに基づき完了判定を実施せよ。
1. **基準抽出**: `requirements.md` の現フェーズ要件と、対象Issueの受入条件。
2. **充足判定**: 実ファイル差分・テスト結果(`npm test`等)と突合。
3. **出力フォーマット**:
   - 判定: [Close可 / Close不可]
   - 理由: 3行以内
   - 未充足事項とアクション: (Close不可時のみ優先度順に列挙)
※未充足時は処理を停止し残タスクを提案。Close可の場合のみ完了宣言。

## コマンド2: 「次フェーズを計画して」
人間の判断依存を最小化し、要件を実装計画に落とし込め。
1. **仮想会議**: `virtual_stakeholder_consensus.md` に従い複数ロールで議論・最適解導出。議論は結論が出るまで最大10ラウンド継続。
2. **結論の反映と退避**: 結論のみをADR(新規起票)やIssue(受入条件)の本文に反映。議事録はコンテキストコスト削減のため、対象ファイルの末尾に「AI読込不要のエビデンス」として分離・退避せよ。
※要件の根幹破壊など不可逆な重大変更に触れる場合のみ人間の承認を要求。

## コマンド3: 「並列実行用プロンプトを作成して」
コンフリクトを排除した複数エージェント用タスク指示書を生成せよ。
1. **分析と分割**: 編集ファイルが重複しないよう複数の直列タスクストリーム(レーン)に分割。I/F先行時はモックで依存排除。
2. **完全並列化ルール**: Stream間の待ち合わせを禁止し、各Streamは他Streamの完了を前提条件にしてはならない。依存があるように見える場合は、共有I/Fの編集を後段の統合Streamへ退避し、本ラウンドでは各Streamが自己完結できるローカル実装・モック・テストダブル・専用fixtureで閉じること。
3. **最大並列数の原則**: コンフリクトが起きない範囲で、並列Stream数を最大化すること。目標並列数は **8** とし、目標に到達できない場合でも、その理由（共有ファイル、責務分離不能、CLI検証不能など）を明示したうえで、到達可能な最大数まで分割すること。分割の優先順は、[A] 機能境界、[B] ディレクトリ境界、[C] テスト資産境界、[D] ドキュメント境界とする。共有ファイル(`extension.ts`, `package.json`, 共有README等)がボトルネックになる場合は、それらを誰にも触らせない並列ラウンドとし、必要なら最後に単独の統合Streamを別建てで生成する。
4. **各Stream内の直列性**: 各Streamは十分な作業密度を持つよう、関連タスクを直列Taskへ束ねること。直列Task数は、**コンフリクトの危険がなく、かつ1回のコミットの規模感として自然な範囲内で最大化**すること。最低でも「仕様確認」「実装」「テスト追加/更新」「CLI検証」「結果要約」を含め、単発作業のみの薄いStreamを量産しない。
5. **分割の品質ゲート**: 生成前に各Streamについて以下を自己点検せよ。
   - 編集対象ファイル集合が他Streamと完全に交差しないか。
   - 完了条件に他Streamの成果物が含まれていないか。
   - 単独でCLI検証可能か。
   - 変更理由が要件またはIssueにトレース可能か。
6. **出力形式**: 回答全体は必ず Markdown 形式で出力すること。各Streamは Markdown 見出し（`####`）を用いて区切り、別セッションへそのまま貼り付けられるプロンプトとして提示すること。
7. **出力フォーマット**: 以下の形式で、別セッションにペーストして即実行可能なプロンプト群を出力。
```text
### [Stream A: 〇〇機能] 用プロンプト
Role: MMI 実行エージェント
対象ファイル: [src/...等] (指定外ファイル編集厳禁)
タスクリスト:
- Task 1: [仕様確認と対象範囲の固定]
- Task 2: [実装/修正]
- Task 3: [テスト追加・更新]
- Task 4: [CLI検証]
- Task 5: [結果要約]
指示: 自律実行プロトコルに従い直列実行。各Task後CLI(npm test等)で検証し、最大3回の自律修復を実施。パスするまで次へ進まない。他Streamの完了待ちは禁止。
検証コマンド: [このStream単独で実行可能なCLI]
完了条件: [他Stream非依存の受入条件]
```
8. **出力時の付帯情報**: プロンプト群の前に「分割方針サマリ」を添え、各Streamの責務・対象ファイル・非対象ファイル・独立性の根拠を1〜2行で明記せよ。
※タスク間の依存関係はStream内に閉じること。Stream間依存は原則禁止。どうしても避けられない場合は、その作業は並列ラウンドから除外し、単独の統合Streamとして分離する。

## コマンド4: 「開発を進めて」
1. 現在のフェーズをクローズする。クローズ不可の場合は並列実行用プロンプトを作成する。
2. 現在進行中のフェーズが存在しない場合は、次フェーズの計画を進める。
